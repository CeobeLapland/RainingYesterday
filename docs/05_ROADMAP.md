# 05 · 分阶段实施计划

> 按"里程碑 M0 → M9"推进，每个里程碑有明确交付物与验收标准。**MVP = M0~M9 全部完成**，覆盖 GDD_v2 的 P0 全部系统，真机能走出"Day 0 → Day 7"的第一周体验。P1/P2 后续里程碑另列，可继续补。

## 0. 使用方式

- 接到一个里程碑，先读它"涉及文档"一栏指到的 `01` / `02` 章节，再读 `03` / `04` 相关约束，然后实现。
- 每个里程碑结束跑一次对应验收标准，通过再进下一个。
- 数据内容与代码解耦：里程碑里的"示例内容"用一份最小 `campus_default` 主题包承载，先跑通再扩内容。

---

## M0 · 工程脚手架

- **目标**：能编译、能跑的空壳 App，依赖、DI、导航、主题就位。
- **涉及文档**：`03`（依赖/构建）、`01 §3`（包结构）、`04 §3/§7`
- **交付物**
  - 单模块 Gradle 工程 + Version Catalog
  - Hilt 装配、Material3 主题、Navigation 骨架
  - 空屏幕：地图 / 我的空间 / 日记 / 图鉴 / 对话
- **验收**：编译通过，五个 Tab 可切换，无崩溃，暗色主题可用。

## M1 · 内容数据管线

- **目标**：`02` 的全部 JSON schema 落地成 Kotlin 模型 + 解析器，一份最小主题包能载入。
- **涉及文档**：`02`（全篇）、`03 §5`、`04 §4`
- **交付物**
  - `domain/model` 枚举与数据类（Place/Npc/Task/Item/Recipe/Event/Rumor/Theme…）
  - `ContentRepository` 接口 + JSON 资产解析实现（含 ignoreUnknownKeys 与合法性校验）
  - `assets/content/campus_default/` 至少含 3 地点、2 NPC、3 物品、2 任务、1 传闻
- **验收**：单元测试能载入示例包；坏 JSON 启动时报错且信息可读；多余字段不崩。

## M2 · 领域引擎核心

- **目标**：世界状态机 + 触发引擎跑起来，这是全项目心脏。
- **涉及文档**：`01 §4`、`02 §1/§3/§4`
- **交付物**
  - `WorldState`（time/weather/season/date）由系统时钟驱动，天气/季节可注入（本地模拟实现）
  - 触发引擎：`Condition` 求值器支持 `02` 全部 kind（time_range/weather/season/near/exploration/relationship/has_item/day_of_week/date）
  - `DerivedState` 计算：当前可见事件、生效传闻、NPC 位置、可刷新资源
- **验收**：JUnit 覆盖各 `Condition` 组合（含 all/any 嵌套）；同一时刻改天气/探索度，`DerivedState` 正确变化。

## M3 · 定位与六边形迷雾

- **目标**：真实坐标落地，迷雾随移动解锁。
- **涉及文档**：`03 §4`、`02 §3`（FogCell）
- **交付物**
  - 定位服务封装，`locationMode`（disable/foreground）可切换
  - osmdroid 底图 + Compose Canvas 叠加层
  - 六边形网格生成、`FogCell` 判定与解锁（进入半径解锁，且分层显现：地点 → 历史 → 传闻 → 异常）
- **验收**：手动点击模拟位置可解锁迷雾（无真机也能验收）；前台定位真机走通；权限被拒降级到模拟模式不崩。

## M4 · 探索 / 足迹 / 地点发现

- **目标**：玩家走进现实世界，"发现"成为一等事件。
- **涉及文档**：`02 §2.1`（place）、`02 §3`（DiaryEntry/EncyclopediaEntry）
- **交付物**
  - 地点发现判定（radius_m）+ "[发现]"反馈
  - 足迹记录（连点成线）、本周步数等统计
  - 地点图鉴条目写入
- **验收**：走近 `old_hall` 触发发现并写图鉴；足迹路线可回看；重启后不丢。

## M5 · 日记 + 记忆节点 + 世界图鉴

- **目标**：灵魂系统落地，记忆成为可收藏、可回访的东西。
- **涉及文档**：`02 §3`（DiaryEntry/EncyclopediaEntry）
- **交付物**
  - 文字 + 照片记忆节点（Photo Picker / CameraX）落在地图
  - 回访触发"你曾经来过这里"
  - 图鉴总分与探索度聚合
- **验收**：新建一条带照片的记忆节点，地图可点开，回访有提示；图鉴完成度实时更新。

## M6 · 采集 + 背包 + 资源货币

- **目标**：探索产出的第一环闭环。
- **涉及文档**：`02 §2.4`（item）、`02 §3`（InventoryItem/PlayerProfile）
- **交付物**
  - 亲临资源点采集（受 weather/time 条件约束）
  - 背包与数量增减
  - 六类资源归类 + 三币（探索量/纪念币/声望）初值
- **验收**：雨夜走到 `old_hall` 采到 `rain_mushroom`，晴天采不到；背包/图鉴/币联动正确。

## M7 · 我的空间（建设 / 种植 / 养鱼 / 加工）

- **目标**：把探索原料变成可见成长，补上《星露谷》式生产建设闭环。
- **涉及文档**：`02 §2.5`（recipe）、`02 §3`（PlantSlot/FishPool/BuildSlot）
- **交付物**
  - 网格化自由摆放（种植台、加工台、鱼池）
  - 种植：进度 = 真实时间 + 天气 + 探索量
  - 鱼池养成与繁殖；简化加工（进料 → 出料）
- **验收**：种下一粒种子，雨天且步数高时进度加速；成熟后进加工，产出进图鉴/送 NPC。

## M8 · 动态世界（事件 + 传闻）

- **目标**：世界"活"起来，传闻给出深层入口。
- **涉及文档**：`02 §2.6/§2.7`、`01 §4.2`
- **交付物**
  - 随机事件按 tier 触发，作为引子导向地点/NPC/传闻
  - 传闻蹲守：满足时空条件可能触发、可落空（may_fail）
- **验收**：`cat_follow` 事件在近图书馆触发；一条传闻夜间蹲守成功/落空两种情况都正确。

## M9 · 存档全量 + 联调封板

- **目标**：Room 全量落盘、进程恢复、MVP 演示打磨。
- **涉及文档**：`02 §3`、`03 §2/§8`
- **交付物**
  - 全部实体的正式 Dao + 数据库版本 + 迁移策略
  - 权限运行时申请、后台杀进程后状态恢复
  - 云存档/多人接口占位（不实现）
- **验收**：真机完整走一遍 Day 0 → Day 7（含首次触发一条传闻/异常入口）；卸载重装存档可迁移恢复（或明确用 JSON 导出兜底）。

## 里程碑依赖与建议顺序

```text
M0 ─ M1 ─ M2 ─ M3 ─ M4 ─ M5 ─ M6 ─ M7 ─ M8 ─ M9  （主线）
               │
               └────────────（M4~M8 依赖 M3 定位与 M2 引擎）
```

- M1 与 M2 可并行（一边定数据、一边写引擎）。
- M5 / M7 依赖 M4 的采集与地点，但彼此可并行开发。
- 每个里程碑完成后更新 `00_INDEX.md` 的文档地图（如有新增文档）。

## 完成标准（MVP 总验收）

1. 数据驱动：换一套主题 JSON 不改代码即改世界。
2. 纯 Kotlin 领域层：引擎单测通过，不依赖 Android/地图。
3. 真机走通"第一周体验"，探索 → 养成 → 深层入口形成闭环。
4. 离线可玩：关网 + 关外部 API 仍能完整游玩 P0 内容。
5. 遵循 `04` 规范，无内容硬编码、无领域层越界。

# 01 · 架构

## 1. 分层总览

```text
┌────────────────────────────────────────────────┐
│  表现层 ui（Jetpack Compose）                    │
│  地图 · 我的空间 · 日记 · 图鉴 · 对话 · AR(P2)   │
│  只读状态、传操作，不懂规则                       │
└───────────────┬────────────────────────────────┘
        状态 ↑        ↓ 操作
┌───────────────┴────────────────────────────────┐
│  领域层 domain（纯 Kotlin，核心）                │
│  · 世界状态机（时间/天气/迷雾/世界条件）          │
│  · 触发引擎（条件 → 内容）                       │
│  · 各系统规则：探索/采集/种植/图鉴/关系/异常      │
└───────────────┬────────────────────────────────┘
      读数据 ↑        ↓ 写存档
┌───────────────┴────────────────────────────────┐
│  数据层 data                                    │
│  内容仓库(JSON) · 存档 Room · 定位 · 真实信号 · REST(后补) │
└───────────────┬────────────────────────────────┘
                ↑ 生成世界 JSON
┌───────────────┴────────────────────────────────┐
│  工具层 editor（开发者编辑器 / 自定义模式）      │
└────────────────────────────────────────────────┘
```

职责边界：上层只依赖下层的接口，下层不反向依赖上层。领域层是整个系统的中枢，其余都是它的"输入输出设备"。

## 2. 两条数据轴（务必分清）

- **世界内容（静态）**：这校园长什么样。以 JSON 文件随包发布或热更新，用 `ContentRepository` 载入。一份。
- **玩家存档（动态）**：你玩到哪、有什么。用 Room 存，`SaveRepository` 读写。每人一份。

两者分离，才支撑周期洗牌、单机/多人切换、换主题图（主题 = 一组世界内容 JSON 的集合）。

## 3. 包结构（单模块 app）

```text
app/src/main/java/com/rainingyesterday/
├── di/                    # Hilt 模块、依赖装配
├── data/
│   ├── content/           # 内容仓库：解析/缓存世界 JSON
│   ├── db/                # Room：Entity、Dao、Database
│   ├── location/          # 定位服务封装
│   ├── signal/            # 真实信号源（天气/季节/校园，模拟兜底）
│   └── remote/            # REST（后补，先留接口）
├── domain/
│   ├── model/             # 纯数据类 + 枚举（世界/玩家模型）
│   ├── engine/            # 世界状态机、触发引擎、系统规则
│   └── repository/        # 仓库接口（数据层实现）
└── ui/
    ├── theme/             # 主题、设计 token
    ├── map/               # 地图 + 六边形迷雾
    ├── space/             # 我的空间（建造/种植/养鱼/宠物）
    ├── diary/             # 日记 / 记忆节点
    ├── collection/        # 世界图鉴
    ├── npc/               # 对话 / 关系
    ├── ar/                # AR 视图（P2 占位，仅接口）
    ├── navigation/        # 路由
    └── components/        # 通用组件
```

`editor`（开发者可视化编辑器）先放独立 package `editor/`，阶段性需求扩大后再拆独立 module。

## 4. 核心引擎

### 4.1 世界状态机

持有一份当前世界状态，随系统时钟推进：

```text
WorldState { time, weather, season, date, worldCondition }
```

天气/季节由外部数据（真实天气 API 或本地模拟）写入，时间由系统时钟驱动。状态变化通知 UI 与触发引擎。

### 4.2 触发引擎

接受"条件"作为输入，命中即产出"内容"。一次判定 = 对一组 `Condition`（见 `02_DATA_MODEL.md`）求值。

```text
条件池(时间/天气/季节/位置/探索度/关系/持有物)
      → 触发引擎判定
      → 触发内容(事件/传闻/异常/NPC作息/资源刷新)
      → 更新世界状态 / 玩家状态
      → 影响下一轮条件
```

传闻、随机事件、异常解锁、NPC 作息、稀有资源刷新、地点微仪式、实拍识别判定，全部由它统一驱动，只靠规则数据不同来区分。

### 4.3 AR 视图（P2 占位，不影响 MVP）

AR 是表现层的可选视图，不进入领域层。其输入与地图叠加层一致，都是触发引擎算出的 `DerivedState`（"该地点此刻该出现哪些虚拟物"），差别只在渲染视口：地图是俯视 Canvas，AR 是第一人称相机。MVP 阶段只保留 `ui/ar` 包占位与 `02` 里的 `ar` 可选字段，不引入 AR SDK，也不在领域层出现任何 AR / 相机依赖。

### 4.4 真实信号（数据层，可配置）

真实天气 / 季节 / 校园信号由 `data/signal` 封装，向领域层暴露 `SignalSource` 接口（真实实现 + 本地模拟实现）。领域层只认接口，不关心信号来自网络还是模拟；外部失败由数据层兜底降级，绝不中断游戏。

## 5. 单向数据流（UI 侧）

```text
用户操作 → ViewModel(intent) → 领域引擎 → 新 GameState → UiState(Flow) → Compose 渲染
```

- 每个屏幕一个 ViewModel，暴露 `StateFlow<UiState>`。
- UI 不发散写状态，所有状态变更都走 ViewModel 进入领域层。
- 领域层产出不可变的 `GameState` 快照，UI 只读。

## 6. 单机 / 多人开关

数据层里"是否展示他人内容"是一个配置项（`PlayerSettings.showOthers`）。开启时才请求足迹/漂流瓶/共享记忆，关闭则完全本地。因为世界内容与个人存档本就分离，多人只是"多了一个展示他人数据的通道"，不影响核心引擎。

## 7. 决策记录

| 决策 | 结论 |
| --- | --- |
| 分层 | 表现 / 领域 / 数据 / 工具四层 |
| 模块 | 单模块 + 包分层（不强拆多 module） |
| 领域层依赖 | 纯 Kotlin，禁止引入 Android / 地图 / Compose |
| 内容存储 | JSON 随包 + 可热更新 |
| 存档存储 | Room |
| 规则 | 数据驱动，规则进 JSON 不进代码 |
| 编辑器 | 内容生产方，只写 JSON，不参与运行时 |
| AR | 表现层可选视图，输入 DerivedState；P2 后补，先留 ui/ar 包 + ar 字段占位 |
| 真实信号 | data/signal 封装，SignalSource 接口，真实优先、模拟兜底 |
| 实拍识别 | CameraX 实时预览 + 已知条目本地匹配，不做通用识别 |
